# КомпМастер Server v2


Серверная версия собрана поверх Beta v11. Дизайн и пользовательские страницы сохранены, а данные вынесены на backend.

## Что уже работает на сервере

- PostgreSQL: пользователи, заказы, статусы, товары и настройки сайта.
- Регистрация и вход с bcrypt-хешированием паролей и httpOnly-cookie.
- Заказ создаётся на сервере, номер `01_000001` генерируется из серверной последовательности.
- Цена и доступное количество перепроверяются на сервере при создании заказа.
- Ручной режим оплаты из Beta v11: заказ создаётся со статусом «Ожидает оплаты», клиент переходит к менеджеру.
- Администратор подтверждает оплату на сервере.
- Через 35 часов после подтверждённой оплаты сервер сам переводит «Формируется заказ» → «В пути».
- Изменение статусов, отмена и удаление заказов — серверные.
- Настройки главной, меню, FAQ, гарантии, категорий и оплаты сохраняются в БД.
- Картинки категорий, фото и видео загружаются на сервер в `/uploads`.
- XLSX можно импортировать через админку.
- Google Sheets API подготовлен: после добавления сервисного аккаунта появляется серверная синхронизация.
- SMTP подготовлен для писем о статусах и восстановлении пароля.
- Архитектура платёжных адаптеров сохранена; ручной режим включён по умолчанию.
- Caddy автоматически получает HTTPS-сертификат после привязки домена.

## Первый запуск на VPS

1. Установить Docker и Docker Compose.
2. Распаковать проект на сервер, например в `/opt/compmaster`.
3. Скопировать `.env.example` в `.env`.
4. Заполнить минимум: `DOMAIN`, `JWT_SECRET`, `POSTGRES_PASSWORD`, `DATABASE_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
5. В DNS домена создать A-запись на IPv4 VPS.
6. Запустить:

```bash
docker compose up -d --build
```

7. Проверить:

```bash
curl https://ВАШ-ДОМЕН/api/health
```

Админка открывается по `https://ВАШ-ДОМЕН/#admin`.

## Обязательно перед публичным запуском

Не используйте старый beta-пароль в публичной версии. В `.env` задайте новый длинный `ADMIN_PASSWORD` и случайный `JWT_SECRET`. Файл `.env` не публикуйте и не кладите в Git.

## Google Sheets

Создайте Google Cloud service account, включите Google Sheets API, дайте e-mail сервисного аккаунта доступ «Читатель» ко всем таблицам и поместите JSON-ключ одной строкой в `GOOGLE_SERVICE_ACCOUNT_JSON`. Затем в админке у категории нажмите «Синхронизировать Google Sheets».

Парсер ищет в первой строке колонки с названиями вроде «Название/Товар», «Цена», «Количество/Остаток». Если структура ваших таблиц другая, адаптируем парсер один раз.

## Почта

Заполните SMTP-переменные. Без них сайт продолжит работать, но письма не отправляются.

## Платёжные системы

Сейчас оставляйте «Ручной режим оплаты». Для конкретного провайдера добавляется серверный адаптер в `src/payment-adapters/`; API-ключи хранятся только на сервере. После установки адаптера провайдера его можно выбирать через существующую вкладку «Оплата».

## Резервные копии

Перед обновлением кода делайте дамп БД и копию volume `uploads`. Код можно обновлять отдельно от PostgreSQL и файлов — заказы и пользователи не должны пропадать при обновлении сайта.

## Что нового в v2

- Двухуровневый каталог: `Комплектующие ПК` и `Периферия` открывают подкатегории.
- `Комплектующие ПК`: видеокарты, ОЗУ, процессоры, материнские платы, M.2, блоки питания, охлаждение.
- `Периферия`: клавиатуры, мыши, микрофоны, наушники.
- Добавлены прайсы: игровые приставки, 3D-принтеры, техника Apple, смартфоны.
- Новые PDF-прайсы перенесены в базовый seed полностью: 39 + 75 + 77 + 132 + 196 позиций.
- Админка категорий поддерживает разделы, подкатегории, перенос между разделами и загрузку своих изображений.
- Обновление поверх Server v1 автоматически добавляет недостающие категории и новые прайсы, не удаляя заказы, пользователей, загруженные картинки и существующие товары старых категорий.

Картинки новых категорий сейчас нейтральные SVG-заглушки. Их можно заменить через `Админка → Категории → Загрузить картинку`; изображение показывается целиком через `object-fit: contain`.
