# Оценка затрат и стратегическая дорожная карта: PoC интернет-магазина → масштабируемая white-label платформа

**Дата подготовки:** 8 сентября 2026 г.
**Аудитория:** руководители и собственники бизнеса без технической специализации
**Валюта всех оценок:** доллары США (USD)
**Горизонт планирования:** 6 месяцев жизненного цикла PoC + перспектива 3 лет для white-label платформы

---

## 1. Резюме для руководства (Executive Summary)

**Что предлагается.** Запустить в «боевых» условиях демонстрационный интернет-магазин (PoC — proof of concept, «проверка концепции»: минимально рабочая версия продукта, созданная быстро и дёшево, чтобы проверить спрос и собрать данные до крупных вложений), собрать за 3–4 месяца реальные данные о поведении покупателей, а затем перестроить его технический «скелет» в переиспользуемую платформу, на основе которой каждый новый брендовый магазин (white-label — «белая этикетка»: одна техническая основа, на которую «надеваются» разные бренды, дизайны и домены) можно будет запускать за дни, а не за месяцы.

**Ключевая особенность модели затрат.** В проекте нет платной команды разработчиков. Всю работу выполняют ИИ-агенты (программы на базе больших языковых моделей, которые пишут код, настраивают серверы и проверяют качество) и автоматизированные процессы под управлением одного человека — собственника. Поэтому в смете **нет ни одной строки «оплата труда разработчиков»** — вместо неё указаны подписки на ИИ-сервисы, оплата их вычислительных ресурсов (токенов), облачная инфраструктура и инструменты мониторинга по официальным прайсам 2026 года.

**Итоговая смета (полный 6-месячный цикл PoC, рекомендуемый вариант):**

| Блок затрат | Сумма, USD |
|---|---|
| Ежемесячные расходы (ИИ-инструменты + инфраструктура + мониторинг + обслуживание) — $220/мес. × 6 мес. | **$1 320** |
| Разовые работы (развёртывание, домен, оценка open-source, рефакторинг) | **$712** |
| Резерв на непредвиденное (15%) | **$305** |
| **ИТОГО за 6 месяцев** | **$2 337** |

Для сравнения: отраслевые оценки содержания малого интернет-магазина силами людей составляют **$5 000–15 000 в год** только на поддержку, без разработки (источник: [Adevs, Software Maintenance Costs, 2026](https://adevs.com/blog/software-maintenance-costs/)). Наша модель укладывается в ~$2 640/год «всё включено».

**Главный стратегический вывод.** Вложение **$650** в перестройку «скелета» платформы и выбор open-source основы (разделы 7–8) окупается **уже при запуске второго магазина**: экономия на одном повторном запуске составляет ~$2 187 (расчёт в разделе 11). При пяти магазинах суммарная экономия — ~$8 700 (ROI ≈ 1 246%).

**Методология.** Документ подготовлен с использованием параллельной работы пяти исследовательских ИИ-под-агентов (sub-agents — вспомогательные ИИ-процессы, выполняющие отдельные задачи одновременно для ускорения). Каждый раздел снабжён атрибуцией: какой под-агент собирал фактуру. Все цены проверены по официальным страницам прайс-листов в сентябре 2026 г.; ссылки приведены рядом с каждой цифрой. Полные исследовательские отчёты сохранены в репозитории: `AI_TOOLING_COST_ESTIMATE_2026.md` и `2026-hosting-pricing-research.md`.

## 2. Обязательные термины простыми словами

| Термин | Простое объяснение |
|---|---|
| **PoC (proof of concept)** | Демонстрационная, «черновая» версия магазина: работает по-настоящему, но без излишеств. Цель — проверить спрос и собрать уроки дёшево. |
| **White-label** | Одна техническая «заготовка» магазина, на которую наносятся разные бренды: логотип, цвета, домен, каталог. Как один и тот же дом с разными вывесками. |
| **ИИ-агент** | Программа-«цифровой сотрудник», которая по заданию человека пишет код, настраивает серверы, ищет ошибки. Оплачивается подпиской или по объёму работы (токенам). |
| **Токен** | Единица измерения работы ИИ-модели (примерно ¾ слова). Цены указываются за 1 млн токенов. |
| **API (программный интерфейс)** | «Розетка», через которую одна программа получает данные или услуги другой (например, магазин запрашивает у платёжной системы списание денег). |
| **Headless-архитектура** | Магазин разделён на «невидимый двигатель» (товары, заказы, оплата — бэкенд) и «витрину» (страницы, которые видит покупатель — фронтенд). К одному двигателю можно подключить много витрин — основа white-label. |
| **IaC (Infrastructure as Code)** | Описание всех серверов и настроек в виде текстовых файлов. Инфраструктуру нового магазина можно «воспроизвести» одной командой, как по чертежу, а не собирать вручную. |
| **SDLC (жизненный цикл разработки)** | Стандартный порядок работ: план → разработка → проверка → выпуск → поддержка. Даёт предсказуемость качества. |
| **CI/CD** | Автоматический «конвейер»: при каждом изменении кода система сама его проверяет и публикует. GitHub Actions — самый распространённый такой конвейер. |
| **ELK** | Набор программ (Elasticsearch, Logstash, Kibana) для сбора журналов работы системы и их отображения в графиках. Мощный, но «тяжёлый» и дорогой для PoC — ниже предложены доступные аналоги. |
| **Дашборд** | Экран с графиками и цифрами «на одной странице» — для быстрых управленческих решений без технических знаний. |
| **Мультитенантность (multi-tenant)** | Режим, при котором одна установленная платформа обслуживает несколько независимых магазинов («квартир в одном доме») с раздельными каталогами, ценами и клиентами. |
| **Open source** | Программы с открытым исходным кодом: бесплатны, их можно свободно использовать и изменять в коммерческих целях (в зависимости от лицензии). |

## 3. Допущения и границы оценки

1. PoC — магазин с небольшим каталогом (до ~500 товаров) и трафиком до нескольких сотен посетителей в день.
2. Жизненный цикл PoC — 6 месяцев, после чего принимается решение о запуске полноценной платформы.
3. Единственный человек-оператор — собственник бизнеса; его время не тарифицируется (не является денежным расходом компании).
4. Все сервисы выбраны с учётом **коммерческого** использования: бесплатные тарифы, запрещённые для бизнеса (например, Vercel Hobby, бесплатный UptimeRobot — [условия UptimeRobot](https://uptimerobot.com/pricing/)), в расчёт не берутся.
5. Цены зафиксированы по официальным страницам прайсов на сентябрь 2026 г.; возможны колебания ±10%.

## 4. Рабочий поток №1. Развёртывание PoC «как есть» + сбор уроков после запуска

> *Атрибуция раздела: фактура собрана под-агентом №1 (стоимость ИИ-инструментов 2026) и под-агентом №2 (облачная инфраструктура 2026). Полный отчёт: `AI_TOOLING_COST_ESTIMATE_2026.md`, `2026-hosting-pricing-research.md`.*

### 4.1. Что делается

Существующий код магазина (репозиторий `kompmaster-server`) разворачивается в интернете «как есть» — без переделки, максимально быстро (2–3 недели работы ИИ-агентов). Одновременно в магазин встраиваются «датчики»: инструменты, которые фиксируют, что делают посетители (что смотрят, где бросают корзину), как быстро работает сайт и где возникают сбои. Эти данные — главный актив PoC: они определят, каким строить будущую white-label платформу.

## 5. Рабочий поток №2. Поддержка, обновления безопасности и платформенные обновления PoC (весь жизненный цикл)

> *Атрибуция раздела: фактура собрана под-агентом №5 (IaC, SDLC, эксплуатационные бенчмарки 2026).*

### 5.1. Что делается

Весь 6-месячный период магазин находится «под присмотром»: обновления безопасности ставятся автоматически, зависимости (сторонние компоненты) обновляются, код проходит автоматические проверки перед каждой публикацией, базы данных копируются ежедневно. Человек-оператор лишь подтверждает готовые изменения.

### 5.3. Почему это дёшево, но не «бесплатно по риску»

- Отраслевой ориентир: ежегодная поддержка ПО = 15–25% от стоимости разработки ([Adevs, 2026](https://adevs.com/blog/software-maintenance-costs/)). При нашей стоимости «разработки» ~$700 это <$200/год — автоматизация укладывается в ориентир.
- Цена пренебрежения безопасностью: средняя стоимость утечки данных для компаний <500 сотрудников — **$3.31 млн**, 60% малых предприятий закрываются в течение 6 месяцев после инцидента ([IBM Cost of a Data Breach Report 2025](https://www.ibm.com/reports/data-breach)). Поэтому бесплатные сканеры (Trivy, ZAP, Dependabot) — самая высокоокупаемая строка сметы.
- Автоматизированное тестирование снижает эксплуатационные расходы на 30–50% ([Pegotec, Industry Benchmarks 2026](https://www.pegotec.net/software-maintenance-cost-percentage-2026-industry-benchmarks)).

### 5.4. Ожидаемая бизнес-выгода

## 7. Рабочий поток №4. Рефакторинг и пересборка «скелета» платформы под white-label

> *Атрибуция раздела: фактура собрана под-агентом №4 (open-source e-commerce платформы) и под-агентом №5 (IaC/SDLC).*

### 7.1. Что делается и когда

После накопления данных PoC (месяцы 3–5) ядро магазина перестраивается по отраслевым стандартам в **платформу-конструктор**:

1. **Headless-разделение**: «двигатель» (каталог, заказы, оплата) отделяется от «витрины». Это магистральный тренд: 67% крупных ритейлеров уже используют headless-архитектуру (Gartner 2026, цит. по [bemeir.com](https://bemeir.com/articles/headless-commerce-architecture-innovation-data-story/)); средний срок окупаемости headless-проектов сократился до 18 месяцев ([tenten.co](https://tenten.co/shopify/headless-commerce-trends-2026/)).
2. **Шаблонизация витрины**: тема/бренд выносятся в конфигурацию — новый магазин = новый конфиг, а не новый код.
3. **IaC**: вся инфраструктура описывается кодом через **OpenTofu** (бесплатно, лицензия MPL 2.0, фонд Linux Foundation — [opentofu.org](https://opentofu.org/manifesto), [github.com/opentofu/opentofu](https://github.com/opentofu/opentofu)); управление состоянием — бесплатно в HCP Terraform Free до 500 ресурсов ([developer.hashicorp.com](https://developer.hashicorp.com/terraform/cloud-docs/overview)) либо в своём R2-хранилище ($0.015/ГБ). Альтернатива: Pulumi Individual — бесплатно для 1 пользователя ([pulumi.com/pricing](https://www.pulumi.com/pricing/)).
4. **SDLC-конвейер**: обязательные автоматические проверки (тесты, безопасность, качество кода) перед каждой публикацией — инструменты из раздела 5, все бесплатны.
5. **Мультитенантность**: закладывается поддержка нескольких магазинов из одной кодовой базы (см. раздел 9, выбор платформы).

### 7.3. Почему рефакторинг окупается (доказательная база)

- Технический долг «съедает» 20–40% стоимости технологических активов компании ([McKinsey, Tech Debt — Reclaiming Tech Equity](https://www.mckinsey.com/capabilities/mckinsey-digital/our-insights/tech-debt-reclaiming-tech-equity)); разработчики тратят 33% времени на обслуживание и переделки ([Stripe Developer Coefficient](https://stripe.com/files/reports/the-developer-coefficient.pdf)). Без рефакторинга каждый следующий магазин наследует и умножает эти издержки.
- Переиспользуемые платформы — подтверждённый тренд: к 2026 г. 80% крупных инженерных организаций создадут платформенные команды (против 45% в 2022) ([Gartner, Platform Engineering](https://www.gartner.com/en/infrastructure-and-it-operations-leaders/topics/platform-engineering)).

### 7.4. Ожидаемая бизнес-выгода

Запуск каждого следующего магазина сокращается с ~6 недель до нескольких дней; стоимость запуска следующего магазина падает с ~$2 100 до ~$150 (расчёт — раздел 11); качество и безопасность одинаковы во всех магазинах, потому что проверяются одним конвейером.

| **Месяц 6+ (после PoC)** | Решение по итогам | — | Продление жизни PoC / миграция на платформу / закрытие | Управляемый выход без «затонувших» затрат |

Критерии успеха PoC (проверяются на 120-й день): ≥1 реальная конверсия в покупку; полнота данных воронок ≥90% дней без сбоев измерений; готовый перечень из ≥10 требований к платформе, подтверждённых данными.

## 11. Варианты переиспользования PoC для white-label и расчёт ROI

> *ROI (окупаемость инвестиций) = (Экономия − Вложение) ÷ Вложение × 100%. Все расчёты — на цифрах разделов 7–9.*

**Базовые константы:**
- Полная стоимость «магазина с нуля» по текущей модели: **$2 337** (раздел 9.3).
- Стоимость запуска следующего магазина на готовой платформе: **$150** (домен $12 + ~$100 токенов ИИ на генерацию конфигурации витрины и каталога + ~$40 первичные лимиты мониторинга; инфраструктура разделяется — см. вариант B). Обоснование: шаблонизация + IaC воспроизводят инфраструктуру «одной командой» бесплатно ([opentofu.org](https://opentofu.org/manifesto)), а мультиканальность Vendure позволяет добавить магазин в существующую установку ([docs.vendure.io — Channels](https://docs.vendure.io/current/core/core-concepts/channels)).
- Инвестиция в перестройку (дополнительно к стоимости простого PoC): **$600 + $50 = $650** (разделы 7.2 и 8.3).

### Вариант A — «Фабрика шаблонов» (рекомендуется)

**Суть:** PoC перестраивается в платформу-конструктор; каждый новый бренд = отдельная установка шаблона (свой домен, своя база, общий код).

**Расчёт на 5 магазинов за 3 года:**

| Путь | Расчёт | Стоимость |
|---|---|---|
| Без платформы: каждый магазин с нуля | 5 × $2 337 | $11 685 |
| С платформой: 1 полная разработка + 4 повторных запуска | $2 337 + 4 × $150 | $2 937 |
| **Экономия** | $11 685 − $2 937 | **$8 748** |

- Окупаемость инвестиции $650: **при запуске 2-го магазина** (экономия $2 187 на одном повторном запуске).
- ROI на 5 магазинов: ($8 748 − $650) ÷ $650 × 100% ≈ **1 246%**.
- Подтверждение из отрасли: headless-архитектура даёт ~80% выгоды «собираемой» платформы при ~40% её стоимости ([bemeir.com](https://bemeir.com/articles/headless-commerce-architecture-innovation-data-story/)); срок окупаемости headless-проектов — 18 мес. ([tenten.co](https://tenten.co/shopify/headless-commerce-trends-2026/)).

**Риск:** каждый отдельный магазин требует своей инфраструктуры (~$20–46/мес. на магазин). При >3 магазинах переходите к варианту B.

### Вариант B — «Одна платформа, много витрин» (мультитенантность)

**Суть:** на базе Vendure (или Saleor) одна установленная платформа обслуживает все бренды: каталоги, цены и заказы разделены «каналами» внутри одной системы ([docs.vendure.io — Channels](https://docs.vendure.io/current/core/core-concepts/channels); [github.com/saleor/saleor — native multichannel](https://github.com/saleor/saleor)).

**Расчёт на 5 магазинов:**

| Статья | Стоимость |
|---|---|
| Платформа (включена в PoC-смету) | $2 337 |
| Доработка до мультитенантности (в рамках рефакторинга, доп. токены) | $150 (разово) |
| Каждый новый бренд: домен + конфиг витрины + почта | ~$60 разово × 4 = $240 |
| Инфраструктура: одна на всех (+$10–20/мес. за рост нагрузки) | ~+$720 за 3 года |
| **Итого 5 магазинов за 3 года** | **≈ $3 450** |

- Экономия против «с нуля» ($11 685): **~$8 200**; против варианта A при 5+ магазинах — ещё ~$2 300 за счёт общей инфраструктуры.
- Предельная стоимость нового бренда: **~$60 разово + $15–20/мес.**
- **Риск:** общая инфраструктура = общая точка отказа; требуется резервное копирование (уже включено, Supabase Pro) и лимитирование нагрузки. Рекомендуемый путь: начать с варианта A, мигрировать в B при 3-м магазине.

### Вариант C — «Клонировать PoC без рефакторинга» (не рекомендуется)

**Суть:** каждый новый магазин — копия текущего черновика PoC без перестройки.

**Почему это дороже:** каждая копия несёт свой технический долг. Отраслевые данные: 20–40% стоимости технологических активов «съедается» долгом ([McKinsey](https://www.mckinsey.com/capabilities/mckinsey-digital/our-insights/tech-debt-reclaiming-tech-equity)); 33% времени разработки уходит на обслуживание и переделки ([Stripe Developer Coefficient](https://stripe.com/files/reports/the-developer-coefficient.pdf)); поддержка legacy-систем с высоким долгом достигает 30–50% от стоимости разработки в год ([Adevs](https://adevs.com/blog/software-maintenance-costs/)).

**Расчёт на 5 магазинов:** 5 × ($2 337 − $650, не тратим на рефакторинг) + рост стоимости поддержки каждой копии на 30–50%/год → 3-летняя стоимость ≈ **$10 200–12 500**, т.е. **дороже варианта A на $7 300–9 600**. ROI отрицательный начиная со 2-го магазина.

### Сводная рекомендация

1. **Месяцы 1–4:** вариант A (фабрика шаблонов) — инвестиция $650 сверх сметы PoC уже заложена в разделы 7–8.
2. **С 3-го магазина:** переход на вариант B (мультитенантность Vendure) — предельная стоимость бренда падает до ~$60 + $15–20/мес.
3. **Вариант C исключить** из рассмотрения как экономически нецелесообразный.
